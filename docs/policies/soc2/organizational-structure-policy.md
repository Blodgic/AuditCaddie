## 1. Purpose

This policy documents [COMPANY NAME]'s organizational structure, reporting lines, and the assignment of security and compliance responsibilities. It supports SOC 2 TSC CC1.2 (Board Oversight), CC1.3 (Structures and Reporting Lines), CC1.4 (Attracting and Retaining Competent Individuals), and CC1.5 (Accountability for Internal Control).

## 2. Governance Structure

### 2.1 Board / Advisory Board

[COMPANY NAME] maintains a [Board of Directors / Advisory Board] that:
- Provides oversight of the company's strategic direction, including security and risk
- Reviews and approves the Information Security Program annually
- Is briefed on significant security incidents and material risks
- Includes at least [one member / an advisor] with technology or security expertise

Board meeting cadence: [Quarterly]

### 2.2 Executive Leadership

| Role | Name | Security Responsibility |
|------|------|------------------------|
| CEO / President | [NAME] | Accountable for overall security program, risk appetite |
| CTO / Head of Engineering | [NAME] | Owns technical controls and engineering security |
| CISO / Security Lead | [NAME] | Day-to-day security program management |
| Legal Counsel / DPO | [NAME] | Privacy compliance, regulatory matters |
| Head of People / HR | [NAME] | Employee security awareness, HR compliance |

### 2.3 Security Reporting Line

The CISO / Security Lead reports directly to the [CEO / CTO]. Security matters are escalated to the CEO and Board as follows:
- **Routine updates:** Monthly security dashboard shared with leadership
- **High-risk findings:** Immediate notification to CEO within [48 hours]
- **P1/P2 incidents:** CEO notified within [1 hour]; Board notified within [24 hours] for material incidents

## 3. Security Roles and Responsibilities (RACI)

| Security Function | Accountable | Responsible | Consulted | Informed |
|-------------------|-------------|-------------|-----------|---------|
| Security Policy Management | CISO | CISO, Legal | Engineering, HR | All employees |
| Risk Assessment | CISO | CISO, Engineering | Legal, HR | Leadership |
| Vulnerability Management | CTO | Engineering | CISO | Leadership |
| Incident Response | CISO | Engineering, Legal | HR, CEO | Leadership, Board |
| Access Control | CTO | Engineering, IT | CISO | HR |
| Privacy Compliance | DPO / Legal | Legal, Engineering | CISO, HR | Leadership |
| Security Training | CISO | HR, CISO | — | All employees |
| Vendor Risk | CISO / Legal | Legal, Engineering | CISO | Leadership |

## 4. Competency Requirements

### 4.1 Hiring Standards

All roles with security responsibilities must have documented qualifications:
- **Engineering roles:** Security-related screening in technical interviews; security background check
- **CISO / Security Lead:** Minimum [5 years] security experience; relevant certifications ([CISSP / CISM / CISA / CEH]) preferred
- **Legal / DPO:** Privacy law expertise (CIPP/E or equivalent preferred for data-heavy roles)

### 4.2 Onboarding

Security-critical onboarding steps for all new hires:
1. Complete security awareness training within [30 days]
2. Sign Code of Conduct and Acceptable Use Policy
3. Complete access provisioning per documented role profile
4. Receive role-specific security briefing for roles handling customer data

### 4.3 Continuing Education

[COMPANY NAME] supports security competency through:
- Annual security training for all employees
- Conference attendance for security team members ([1 conference per year])
- Certification support for key security roles
- Security team participation in [ISAC / security community]

## 5. Accountability Mechanisms

[COMPANY NAME] ensures accountability for internal control responsibilities through:
- Annual performance reviews include security KPIs for relevant roles
- Security incidents caused by policy violations are tracked in personnel records
- Control deficiencies are assigned owners with deadlines in [TICKETING SYSTEM]
- Disciplinary action is applied consistently for policy violations per the Code of Conduct
